# Agents Anywhere 2.0.27

## 本次改动

- **本机直连：读写都通了**。连接器在 `127.0.0.1` 上开的端点原先只读，现在也接受 `session.send_message`——用户刚敲下的那条消息直接交给本机的运行时，不必先出公网再回来。
- **服务端仍然是权威，只是不再挡在消息前面**。连接器一直在盯着它驱动的运行时，并把观察到的东西走**同一条 ingest 路径**上传，所以会话状态照旧汇总到服务端，其他机器照旧从服务端了解每台设备的每个会话。本机直连**不产生任何只有本机才知道的事实**。
- **本地直连跳过的是服务端的「发送前」管线**：归属与只读校验、忙碌排队、能力检查、附件解析。这些**没有**在本机复刻——所以桌面端只在本地明确可行时才走本机，**任何失败都回落服务端**：会话未知、描述符读不到、连接器拒绝、socket 断开、超时、带附件的消息，一律走原路。
- **桌面端只拦截两条路由**：`POST /sessions/{id}/runtime/messages`（发消息）与 `GET /sessions/{id}/runtime/state`（读状态）。其余一切照旧走服务端。
- **描述符自愈**（实机发现的 bug）。端点会在文件被删或被人覆盖时把它写回来。实机观察到的现象是：端点在监听，而描述符**已经不存在**——因为一个短命的第二个连接器上线时覆盖了它、下线时删掉了「自己的」那一份，留下仍在服务的那个进程无迹可寻。客户端读不到描述符就完全用不上这条通道。
- **端点现在也接受字符串路径**（跨语言测试发现的 bug）。原先只接受 `Path`，外部调用方传字符串会以 `AttributeError` 失败——仓库内的测试一直传 `Path`，所以从没碰到。

## 为什么服务端不需要重新部署

- 本次改动**只在连接器与桌面端**，服务端一行没改，镜像仍是 2.0.26。
- 两半的兼容性靠能力声明而不是版本号：连接器只在服务端声明 `ingest.encodings` / `ingest.resumable` 时才用压缩与续传，所以**服务端 2.0.26 + 连接器 2.0.27** 是正常组合。

## 测试

- Connector：**1057 通过**。
- 桌面端主进程：**129 通过**（含 14 个本机直连用例、1 个跨语言端到端）。
- 服务端：**966 通过 / 18 跳过**。
- **跨语言端到端**：桌面端真实的 WebSocket 客户端连**真实的 Python 端点**（同一个类，Connector 跑的就是它），握手、令牌、请求/响应形状、拒绝路径都是真的走了一遍。这条用例做过**负向对照**：把断言改错它必须失败——它确实失败，证明用例真的在跑，而不是悄悄跳过。
- **变异验证**：把写方法从白名单移除（2 个用例失败）、给端点换成独立 dispatcher（1 个失败，那正是「本地写入仍会上报服务端」的保证）、去掉描述符自愈（2 个失败）。
- **一个自欺的测试被抓住并修掉**：跨语言用例最初因为路径算错而走了「跳过」分支却报成通过。跳过现在会**失败**，因为一个悄悄什么都没做的测试比没有测试更糟——它看起来像证据。
