# Agents Anywhere 2.0.30

这是一个**大版本合并**：官方 `anywhere-labs/Agents-Anywhere` 的 **249 个提交**全部并入本仓库（分叉点 2026-09-17，我们领先 164 个提交）。本次发布同时保留了本仓库自己的全部改动。

## 本次合并带来的重要更新

### 客户端功能

- **斜杠指令菜单**：Web、Desktop、Android、iOS 四端对齐，支持参数补全与命令结果回显。
- **侧边栏改为拖动排序**：关掉按活跃度自动排序，顺序存库、跨设备同步；随后官方又移除了手动拖动排序（见下）。
- **会话自动归档**：闲置 30 天的会话自动归档，发消息即恢复；侧栏会话超过 50 条折叠到「显示其余」。
- **会话标题规范化**：新建会话时客户端传来的标题合并空白并截到 48 字，Codex 会话不再顶着整段首条消息当名字。
- **单行会话列表**：可在设置里切换。
- **项目会话预览**：每个项目预览 8 条会话，会话上下文改为项目优先。
- **Desktop 内置 CPython**：连接器不再下载或借用本机 Python，只打包连接器源码，并加了 Python 下载镜像。
- **公告**：启动与回到前台时以 sheet 展示。
- **忘记密码、团队分页、管理员跳过邮箱验证**。
- **iOS 大量改进**：设备页按 Android 与 Web 重做、流式回复渲染性能（10 Hz 批次、逐批字形揭示）、新会话页的设备与 Agent 命名、目录选择器等。

### 重要修复

- **桌面端与连接器的启动检查失败时显示真实原因**；**锁端口被系统拒绝时不再阻塞**。
- **看板顶部卡片改为统计整个选定区间**，不再只显示结束日期当天。
- **新建会话的侧栏占位标题与请求标题一致截到 48 字**，发送后不再闪出整段首条消息。
- **DSH 端点回退**：固定端点不可用时尝试旧端点，兼容 2.0.3 之前的连接器。
- **快速设置里每种 Agent 只显示一次**；指令不可用时说明原因，成功反馈改用 toast。
- **Android 移除设备操作菜单里的「重新连接」**。

### 官方先加后撤的两项

- 侧边栏手动拖动排序与其存库记录（`v2_39` 加入，`v2_41` 移除）。
- 会话闲置自动归档（`v2_38` 加入，`v2_40` 移除）。

## 本仓库保留并继续维护的功能

合并过程中逐项核对这些功能没有被官方的改动覆盖或删除：

- **本机直连**：连接器在 `127.0.0.1` 上的端点（读 + 发消息），桌面端本地优先、任何失败回落服务端；发消息仍会异步汇总到服务端，服务端保存的不会重复。
- **ingest 传输**：请求压缩、分片续传、字节预算分批、能力协商。
- **服务端请求体限流与解压中间件**。
- **消息删除**（含 `timeline_items.hidden_at` 与 `timeline_item_hides` 幂等表）。
- **运行中排队发消息**：Web、Desktop、Android 三端。
- **Linux 桌面构建**：官方删掉了 Linux 目标，本仓库继续发布 AppImage 与 deb。
- **实时更新修复**：本仓库先修的「Redis 订阅断开后不再恢复」，官方有更完整的实现（另有 `connection_lost` 事件、`recovery_signal` 让 socket 主动恢复、`healthy` 属性，并关掉 redis-py 的静默重连），本次采用官方版本。

## 数据库迁移

官方的迁移编号 `v2_36`–`v2_41` 与本仓库原来的 `v2_36`–`v2_38` **撞车**（编号相同、内容不同，语义无重叠）。处理方式：

- 官方 `v2_36`–`v2_41` 保持原样。
- 本仓库的三个迁移重编号为 **`v2_42_jupiter`**、**`v2_43_jupiter`**、**`v2_44_jupiter`**，接在 `v2_41` 之后；文件名与 revision 都带 `jupiter` 后缀，便于与官方链区分。
- 链头为 `v2_44_jupiter`，schema version 仍报 **`2.44`**。

**已经部署过的环境需要注意**：如果数据库当前标记在 `v2_38`（本仓库原来的那个），合并后这个标记会被理解成**官方**的 `v2_38`，官方的 `v2_36`–`v2_38` 会被跳过。正确做法是：

```bash
alembic stamp v2_35
alembic upgrade head
```

本仓库的三个迁移**都有幂等保护**（表已存在就直接返回），所以重复执行是安全的空操作。
