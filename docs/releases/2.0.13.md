# Agents Anywhere 2.0.13

## 修复：队列消息发不出去，也删不掉

在 GCFM 项目里排队的那条消息卡住了：**没发出去，也删不掉**。两个独立缺陷叠加。

### 1. 队列消息没有走「排队」这条路

派发时调用普通发送路径，**没有带 `queueWhenBusy`**。运行时读不出状态（繁忙、超时）
时被判成**错误**而非**繁忙**，消息永久失败，显示：

```
runtime did not report its state in time
```

现在派发带上该标志；运行时整个读取窗口无响应时，消息**退回队首**等下次重试。

### 2. 失败的消息删不掉

删除要求 pending 状态。一旦失败就永远无法清除，每次删除都返回
「queued item is no longer pending」。

现在删除接受**仍在队列中的任何条目**（含失败的）。`sending`（正在派发）与
`sent`（已成为回合）仍受保护。

> 那条卡住的消息已从服务器清除。

## 新功能：删除自己的消息

**桌面端、Web 控制台、Android 三端一致。**

**为什么是「隐藏」而不是真删**：会话时间线是**运行时历史的镜像**，而 DSH、Codex、
Claude **都没有删除接口**。直接删行的话，**下次同步就会恢复它**。

所以删除是**本地标记**：

- 标记存在独立列 `hidden_at`，**不在运行时写入路径里**，因此后续同步不会清掉它
- 展示读取过滤隐藏项；同步读取**不过滤**，避免在过滤背后重新插入

测试覆盖：删除 → 用新版本号重新同步同一 id → **保持删除状态**。
删除会推送到所有打开的客户端，无需刷新。

### Android 附带修复

消息旁的按钮此前被包在 `DisableSelection` 中，该包装在部分 Compose 版本上会**吞掉
点击**，导致**复制按钮同样点不动**——这是既有缺陷，本次一并修复。

数据库结构 `v2_37`。
