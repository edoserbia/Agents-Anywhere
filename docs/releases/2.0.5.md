# Agents Anywhere 2.0.5

本记录覆盖服务端与两个客户端。数据库 revision 保持 `v2_36` 不变。**本次的主要变化是服务端迁移到新主机 `closex.cc`。**

## 服务端迁到新主机

服务端此前部署在 `124.220.147.199`，现已迁移到 **`https://closex.cc`**：

| | 旧主机 | 新主机 |
| --- | --- | --- |
| API / Web 控制台 | `http://124.220.147.199:4000` | **`https://closex.cc`** |
| 客户端下载页 | `http://124.220.147.199:4001` | **`http://closex.cc:4001`** |

迁移内容：

- 全部会话数据（945 个会话、22 万条时间线条目、192 个项目、2 个连接器、1 个账号）已完整迁移，传输后逐字节校验哈希一致。
- 连接器令牌与登录会话**保持有效**：`AGENT_SERVER_SECRET` 与数据库密码沿用原值，已登录的设备无需重新登录。
- 客户端内置的默认服务器地址已改为 `https://closex.cc`。

旧主机仍保留原样运行，可作为回滚目标。

## 客户端变化

- **默认服务器**：全新安装默认连 `https://closex.cc`；已安装的设备保留原有配置。
- **更新检查指向可用地址**：此前「检查更新」读到的下载地址是一个 404 的路径，提示更新却无法下载。现在指向本项目的下载页。
- **桌面客户端下载入口**同样指向新下载页。

## 部署说明

新主机上同时运行着 VPN（sing-box）与另一套 Web 服务（Caddy + sub2api）：

- Agents Anywhere 只占用 `4000`（API/控制台）与 `4001`（下载页），与旧主机相同。
- `closex.cc` 的 Caddy 配置中，`/vpn/*` 由原有 matcher 处理，**顺序与内容均未改动**；其余路径转发到 Agents Anywhere。改完后已验证 VPN 订阅路径仍返回 200。
- PostgreSQL 与 Redis 不对主机暴露端口，仅在 compose 内部网络可达。

新主机的登录方式记录在[部署文档](../deployment-hosts.md)。

## 升级

服务端与客户端建议一起升级。数据库无需迁移（`v2_36` 未变）。

登录信息与连接器令牌不变，**不需要重新登录**；若客户端仍指向旧地址，在登录页把服务器地址改为 `https://closex.cc` 即可。

## 版本号

`server/agent_server/core/version.py`、`desktop-workbench/package.json`、`android/app/build.gradle.kts` 的 `versionName` 必须同时为 `2.0.5`；测试 `tests/test_version.py` 会强制校验三者一致。
