# Agents Anywhere 2.0.28

## 本次改动

- **本机直连不再绕过「只读」与「归档」**。会话没被接管（takeover 关闭）就是只读的，归档会话不接受任何写入——这是**机主的决定**，不是传输细节。桌面端现在从服务端读到这两个字段，只读会话**根本不尝试本地写入**，直接回落服务端（由服务端给出它本该给的那个拒绝）。
- **发消息必须带 `clientMessageId`**，否则不走本地。没有这个 id，一次重试和第二次发送**无法区分**，而服务端保存的是运行时产出的东西——消息就会在时间线上出现两次。桌面端渲染器本来就会生成它。
- **投递结果不明时，绝不改走服务端**。本地请求已经上了线、但回包丢了（socket 断开、超时）——这一种情况**不再回落**，而是把失败报给调用方，并带上它自己的 `clientMessageId`，所以重试是幂等的而不是重复的。其余一切失败（连不上、鉴权不过、描述符读不到、服务端不认识这个会话）仍然照旧回落：那些是干净的「没发生」。

## 实机验证（这一次是真的发出去了）

用**真实运行中的连接器**、对着一个**服务端已登记、可写、空闲**的临时会话，走本机端点发了一条真实消息：

- **运行时确实执行了**：codex 会话文件里 `task_complete` **恰好 1 个 turn**，助手回了「好的，已忽略。」。
- **状态异步汇总到了服务端**：约 160 秒后出现在服务端时间线里——**这正是本机直连应该有的样子**（本地立即发出，服务端稍后收敛）。
- **服务端只有一份**：含该消息的条目 `role=user` **恰好 1 条**；静置 3 分钟复查**仍是 1 条**，没有迟到的重复。
- 负载里标记出现 2 次，是「消息正文」+「`source.clientMessageId`」——**同一条消息**，不是两条。

## 前一轮验证为什么一开始没通过

第一次我拿连接器 `session.discover` 列出的会话去发，服务端时间线始终是 0 条。原因不是直连坏了，而是**那个会话服务端根本不认识**（连接器会列出服务端从未登记过的本地会话），服务端自然无处存放它的事件。换成服务端已登记的会话后一次通过。这一步也顺带暴露了上面那条「只读会话」的缺口。

## 测试

- 桌面端主进程：**140 通过**；Connector：**1057 通过**；服务端：**966 通过 / 18 跳过**。
- **变异验证**：去掉只读/归档闸门 → 2 个用例失败；把「投递不明」改回回落 → 用例失败；去掉凭证转发 → 用例失败。
- **一个测不出差别的测试被修掉**：只读用例原先只断言「回落了」，可闸门被拿掉后它**照样回落**（调用被发起、失败、然后回落），所以那个断言证明不了任何事。现在它断言**根本没有发起调用**，并配了一个「可写会话确实会发起调用」的对照。
