# Agents Anywhere 2.0.12

## 修复：队列消息发不出去，也删不掉

你在 GCFM 项目里排队的那条消息卡住了：**没发出去，也删不掉**，提示
「queued item is no longer pending」。这是两个独立缺陷叠加。

### 1. 队列消息没有走「排队」这条路

派发队列消息时调用的是普通发送路径，**没有带 `queueWhenBusy`**。于是当运行时
一时读不出状态（繁忙、超时）时，它被当成**错误**而不是**繁忙**：

```
状态：failed
原因：runtime did not report its state in time
```

消息就此永久失败——**这恰好与队列的用途相反**。

现在派发时带上该标志；若运行时整个读取窗口都无响应，消息会**退回队首**等待下次
回合结束时重试，而不是判死。

### 2. 失败的消息无法删除

删除要求消息处于 **pending** 状态。一旦派发失败，它就永远无法清除——每次删除都
返回「queued item is no longer pending」，界面上留下一条**任何操作都无法解决**的条目。

现在删除接受**仍在队列中的任何条目**，包括失败的。两类仍然受保护：
- `sending` —— 正在交给运行时，删除会与派发竞争
- `sent` —— 已经成为一次对话回合，没有可删的东西

编辑仍然只针对 pending 条目。

> 你那条卡住的消息我已经从服务器上清掉了。

## 新功能：可以删除自己发的消息

现在可以删除对话里的消息。

**为什么是「隐藏」而不是真删**：会话时间线是**运行时历史的镜像**，而 DSH、Codex、
Claude **都没有提供删除接口**（实测均返回 method not found）。如果直接删掉数据库
行，**下一次同步就会把它恢复**——因为运行时仍在报告这条消息。

所以删除是**本地标记**：

- 标记存放在独立的列里，**不在运行时写入路径覆盖的范围内**
- 因此后续同步更新这条消息内容时，**不会清掉标记**
- 明文读取会过滤掉被隐藏的条目；同步用的读取**不过滤**，避免在过滤背后重新插入

已用测试验证：删除一条消息 → 用新版本号重新同步同一个 id → **它保持删除状态**。

删除会同步到所有打开着的客户端（桌面端、Web 控制台），无需刷新页面。

数据库结构 `v2_37`。

## 补充（同一版本内）

Android 端也补上了消息删除入口，三端现已一致。同时修复了一个**此前就存在的缺陷**：
消息旁的按钮被包在 `DisableSelection` 里，该包装在部分 Compose 版本上会吞掉点击事件，
导致**复制按钮同样无法点击**。按钮已移出该包装。
