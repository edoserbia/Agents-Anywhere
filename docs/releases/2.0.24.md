# Agents Anywhere 2.0.24

## 本次变化

- **修复接管 OpenScience 会话后发消息失败**：平台接收消息前要先读一次会话状态，而这次读取在返回前会顺带发布一条状态通知；通知与历史上传共用同一条 HTTP 队列。会话历史很大时（实测单次快照 600–900 条）队列会被填满（上限 1024），发布通知的调用就此阻塞——状态读取永远不返回，平台等满 10 秒后报 `runtime did not report its state in time`，消息没有发出去。现在入队不再无限阻塞，并且「最新值」通知（会话状态、来源、完整时间线快照）只保留每个会话的最新一条、放在队列之外。
- **修复 OpenScience 会话时间线停止更新**：OpenScience 把仍在流式输出的消息标成 `inProgress`，而平台的状态枚举里没有这个词，导致**整批** `timeline.sync` 被拒绝——不是一条消息不同步，而是这个会话的历史从此不再更新。Connector 现在映射为 `running`；Server 侧同时接受 `inProgress`/`completed`/`error` 等别名，老版本 Connector 不会因为同一个词被整批拒绝。
- **状态读取不再被通知拖累**：即使通知发布失败，`session.state` 也照常返回；平台本来就会从这次响应里落库。

## 实测

- 空闲会话上连续发消息全部返回 200 并带回 runID（模型 `gpt-6.1 sol`、思考强度 `extra high`）。
- CVPR 会话的时间线从卡在 12:24 恢复为持续同步（`nextSeq` 79 → 154，最新条目延迟约 30 秒）。
- 修复前队列每 40 秒即满并丢弃通知，修复后不再出现。
