# Agents Anywhere 2.0.3

本记录覆盖服务端、Desktop 与 Android 客户端。服务端数据库 revision 由 `v2_35` 升到 `v2_36`（新增会话消息队列表），服务端与客户端版本号保持同一次发布一致。

## 产品变化

### 消息队列（三种引擎通用）

一个会话同一时刻只跑一个回合。在此之前，运行中再发消息会被拒绝（HTTP 409），消息直接丢失。

2.0.3 引入持久化队列：

- 运行中发送的消息进入队列，显示在输入框上方，**当前任务结束后自动按顺序发送下一条**。
- 队列中的消息可以**就地编辑或删除**；已交给运行时的消息不可再改，否则会谎报实际执行过的内容。
- Codex、Claude、DSH 三种引擎行为一致。
- 队列持久化在 `session_message_queue` 表，服务重启不丢。

### 修复 Android 端「只能观看、无法介入」

两个独立原因，症状相似：

1. **运行中无法输入**（输入框提示"发送中断，或等待当前回合结束"）。DSH 引擎不支持中途插入（`steerTurn: false`），旧逻辑把"运行中且不能 steer"当成"不能发送"，于是输入框锁死、发送与停止按钮全部变灰。但 DSH 支持 `session.send_message`，正确行为是**排队**而不是拒绝。
2. **任务结束后仍提示"当前运行时状态下不可发送消息"**。服务端在连不上连接器时会把持久化的能力事实下发；若这些事实早于该会话的运行时实例，则不含匹配项，所有能力都渲染为"不支持"。而这份快照的版本号是**会话时间戳**（约 10¹⁵），远大于运行时的真实计数（约 4.7×10⁴），于是永久压住真实能力。

修复分三处：

- 服务端在下发能力时带上来源标记；**空结论（全部不支持）不再下发**，但确实含有可用能力的回退结果仍照常下发（连接器只是离线时不影响使用）。
- 客户端识别"占位符"，**不让它压过真实能力**，并在发现更优能力时自愈。
- 能力查找不再要求运行时实例 id 完全相等：会话的生命周期长于它所属的运行时实例，实例 id 变动不应让能力消失。

### 时间戳

每个时间线条目都会显示它**被服务端首次看到的时间**，格式 `[MM-DD HH:mm]`，使用读者本地时区：

- 放在条目上方，折叠状态下同样可见，便于判断某次回复或动作是何时开始的。
- 数字格式固定，不随语言变化，方便纵向比较；省略秒与年份，让它足够短、能贴在每一行上方而不喧宾夺主。
- 乐观消息（服务端尚未确认）不显示时间戳，而不是显示一个不真实的时间。

### 过程自动折叠（2.0.1 已引入，此处一并说明）

一个回合的推理、工具调用、文件变更与子 Agent 调用折叠成一行，默认收起：

- 当前正在执行的回合展开以便观察进度，**回合结束后自动收起**，只保留总结性回复。
- 可点击展开/收起；读者手动展开的块不会被自动收起覆盖。
- Desktop 右侧提供历史请求列表，Android 顶部提供历史按钮，均可跳转到任意历史请求。

### 新装即可用

全新安装的 Android 客户端默认连本服务器，登录页的"自己的服务器地址"已预填，一步即可连接。已装用户保留其原有配置。

## 数据库

`v2_36` 新增 `session_message_queue`：

| 列 | 说明 |
| --- | --- |
| `id` | 队列项 id |
| `session_id` | 所属会话（外键，级联删除） |
| `position` | 提交顺序，决定发送次序 |
| `status` | `queued` / `sending` / `sent` / `failed` |
| `content` | 消息正文 |
| `attachments_json` | 附件引用（JSON） |
| `client_message_id` | 客户端幂等 id |
| `error_code` / `error_message` | 发送失败原因 |

索引 `idx_session_message_queue_position (session_id, position)` 支撑按序取队首。

## 升级

服务端与客户端需一起升级。旧客户端连接 2.0.3 服务端仍可登录，但队列与"不可发送消息"的修复同时涉及两端，需要一起更新。

服务端升级会自动执行 `v2_36` 迁移。回滚前建议先备份数据库。

## 版本号

`server/agent_server/core/version.py`、`desktop-workbench/package.json`、`android/app/build.gradle.kts` 的 `versionName` 必须同时为 `2.0.3`；测试 `tests/test_version.py` 会强制校验三者一致。

发版用 `devtools/release.sh <版本号>` 一次完成版本号提升、构建、上传、校验和下载页更新，详见[开发指南](../development.md#发版必须同步下载页)。
