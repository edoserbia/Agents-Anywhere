# Agents Anywhere 2.0.4

本记录覆盖服务端、Desktop 与 Android 客户端。数据库 revision 保持 `v2_36` 不变——本次只改渲染与发布流程，未改数据契约。

## 产品变化

### 时间戳改为 `[MM-DD HH:mm]`

2.0.3 的初版是 `[YYYY-MM-DD HH:mm:ss]`。秒与年份在读对话时从来不是重点，而过长的前缀会和它标注的那一行抢注意力。

现在每条消息与动作上方显示 `[MM-DD HH:mm]`（本地时区）：

- 折叠状态下同样可见，所以能判断某个动作是何时开始的。
- 数字格式固定，不随语言变化，便于纵向比较。
- 无法解析的值渲染为空而不是 `Invalid Date`；乐观消息（服务端尚未确认）不显示时间戳，而不是编造一个时间。

### 过程折叠

一个回合的推理、工具调用、文件变更折叠成一行摘要（如「推理了 1 次，执行了 3 次工具」）：

- **执行中展开**以便观察进度，**回合结束后自动收起**，只保留总结性回复。
- 点击可随时展开/收起；读者手动展开的块不会被自动收起覆盖。

## 发布流程

版本号此前只在需要时手动提升，导致 2.0.3 的产物更新了、下载页却仍写着 2.0.3。已发布的安装包不会因为源码变化而更新，读者也无法判断自己装的是哪一版。

现在：

- **每次客户端改动都提升版本号**（默认补丁位加一），五个位置一起改，含 `AppConfig.UPDATE_DOWNLOAD_URL`。
- `devtools/release.sh <版本号>` 一次完成：提升版本号、构建 APK 与 DMG、上传、逐字节校验、写 `SHA256SUMS.txt`、重新生成下载页并确认页面显示新版本。任一步不满足即失败退出。
- 服务端部署与提交仍为手动，因为时机取决于部署环境。

## 升级

服务端与客户端需一起升级。数据库无需迁移（`v2_36` 未变）。

## 版本号

`server/agent_server/core/version.py`、`desktop-workbench/package.json`、`android/app/build.gradle.kts` 的 `versionName` 必须同时为 `2.0.4`；测试 `tests/test_version.py` 会强制校验三者一致。发版见[开发指南](../development.md#发版必须同步下载页)。
