# Agents Anywhere 2.0.11

## 重要修复：DSH 任务无法同步

在 DSH Desktop 2.0.13 里提交任务后，Agents Anywhere 看不到任务和过程。

**先说明一点**：这不是 DSH 2.0.13 的协议变更。实测其桥接协议与之前完全兼容
（`protocolVersion: 1.0`、`projectionVersion: 2`、确认时限未变）。

真正的原因是**上行带宽**。实测本机到服务器的速度：

| 方向 | 速度 |
| --- | --- |
| **上行**（连接器 → 服务端） | **19.4 KB/s** |
| 下行（服务端 → 客户端） | 216 KB/s |

DSH 桥接给每个事件批次的确认时限是 60 秒。在 19.4 KB/s 下，**1 MB 需要 54 秒**，
任何更大的历史都无法在时限内确认——最大的会话历史有 14.2 MB。

随之暴露出三个独立缺陷，都已修复：

### 1. 上传超时过短（连接器）

上传超时固定 60 秒，等于假设整个快照能在一分钟内传完。改为 900 秒，并可用
`AA_CONNECTOR_INGEST_TIMEOUT_SECONDS` 覆盖。

### 2. 运行时串行同步（连接器）

扫描器逐个运行时同步，一个慢的 Codex 读取（实测 61 秒）会**阻塞 DSH 的确认**。
两者互不相关，现在并发执行。

### 3. 能力重发布阻塞响应（服务端）

该操作遍历连接器的**全部 633 个会话**，而 ingest 处理器同步等待它。
实测单次请求 **61.5 秒和 65.0 秒**——正好超过桥接的 60 秒时限。
现在改为后台任务，实测服务端最慢操作从 **65,000ms 降到 274ms**。

### 4. 就绪判断可能永久等待（连接器，此前已修复）

DSH 只在收到 `session.inventory.complete` 时才离开 `starting`，而该状态下
supervisor 拒绝一切操作。该事件不保证送达，原代码无超时。
现在 90 秒上限后即视为可用。

## 实测结果

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 桥接同步失败 | 每约 60 秒一次，50 次全部重来 | **0 次（持续观察）** |
| 服务端最慢操作 | 65,000 ms | **274 ms** |
| DSH 状态 | `starting` | **`running`** |
| 任务与过程同步 | 不同步 | **实时同步**（已验证到当前对话的最新条目） |

## 已知限制

上行带宽 19.4 KB/s 是链路事实，代码无法改变。超大历史会话的首次全量同步仍会较慢。
进一步的改进方向：增量同步（只传变化部分）、分块上传、或更大的确认预算。
