# Agents Anywhere 2.0.31

修复运行中发消息的排队功能。

## 排队消息现在真的会进队列

**问题**：在一个任务运行中再发一条消息，它会直接出现在对话流里，看起来已经发出去了，但实际上没有被处理；输入框上方也不会出现队列面板，所以排队、编辑、立刻插入、删除这些操作都用不上。

**两个原因叠在一起：**

- **服务端只信运行时的实时自报**。发送前会向运行时查一次状态，而 DSH 在回合进行中会报 `idle`。服务端因此走了「立即发送」分支，把消息直接交给一个正忙的运行时，被丢掉了。会话自己的状态一直是对的（客户端据此显示「正在工作」），却没有参与判断。现在以会话状态兜底：会话状态不是空闲就按忙处理并排队。
- **Web 与 Desktop 在排队时仍然把消息乐观地塞进对话流**。它根本不属于这一轮的对话，服务端还把它握在队列里。现在排队时不再这样做，改由队列面板显示——那才是能编辑、插入、删除它的地方。

Android 本来就处理正确：它在服务端返回 `queued` 时会移除那条乐观消息。

## 队列面板

三端都已有队列面板，位于输入框上方，**默认折叠**，标题带条数，展开后可编辑、立刻插入、删除：

- Web ✅
- Desktop ✅
- Android ✅

## 上一版（2.0.30）以来的另一处修复

队列的**派发**在合并官方 249 个提交时被破坏了：官方的 `runtime.statusChanged` 不再产出 effect，而派发读的正是那个 effect 里的状态，于是派发永远不触发。生产日志里六个小时没有任何派发记录。现在改为在运行时转为空闲时按 runtime 解析出它名下的会话再派发，派发本身幂等，队列为空就是一次空操作。
